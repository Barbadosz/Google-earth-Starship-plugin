# Data sources and data quality

Rule of the project: **no fabricated telemetry**. Every point and event carries a quality level and a source name.
Data without an origin is not accepted.

## Sources used in M1

| Data | Files | Source | Quality | Licence |
|---|---|---|---|---|
| Demo mission (name, events, launch time) | `data/missions/demo-ift.json` | Illustrative approximation, not derived from official flight data | `Simulated` | MIT (this repository) |
| Demo planned trajectories (Starship, Super Heavy) | `data/trajectories/demo-ift-starship-planned.json`, `data/trajectories/demo-ift-superheavy-planned.json` | Illustrative approximation, not derived from official flight data | `Simulated` | MIT (this repository) |
| Placeholder 3D models and icons | `assets/` | Generated by `tools/assets/Generate-Assets.ps1` | n/a (not flight data) | MIT, see [assets-licenses.md](assets-licenses.md) |

**The demo data is illustrative.** It is a rough, made-up shape of a generic Starship-like suborbital flight (a launch
from south Texas to an Indian Ocean splashdown). Positions, altitudes, timings and implied speeds are not official
numbers and not telemetry. This project is not affiliated with, endorsed by or connected to SpaceX.

The raw input files are kept unchanged in `data/`. All processing (densification, orientation, KML) is done at build
time and can be repeated.

## Planned sources (future, not yet used)

These are ideas for M3 and later. **None of them is used or implemented now**, and none is included in the repository.
Before any is used, its access terms and licence must be checked and written here and in
[assets-licenses.md](assets-licenses.md).

- Official regulator documents for planned flights (for example FAA licence and airspace documents).
- Operator publications (for example mission pages and public webcasts).
- Notices to Air Missions (NOTAM) and maritime hazard notices for closure areas.
- Public tracking and trajectory reconstructions made by third parties (only if the licence allows it).

## Data quality levels

The `DataQuality` enum (`StarshipMissionTracker.Core/Enums/DataQuality.cs`) is ordered from worst to best:

| Level | Meaning |
|---|---|
| `Unknown` | Origin or reliability not known. |
| `Simulated` | Made up for illustration or a model run (the M1 demo data). |
| `Estimated` | Computed from other data (interpolated, derived). |
| `Reconstructed` | Rebuilt from public observations or documents after the fact. |
| `Published` | Taken from an official published source as given. |
| `Measured` | A real measurement (for example telemetry). |

Order: `Unknown < Simulated < Estimated < Reconstructed < Published < Measured`.

### Rules

- A point or event that is **densified or derived** (inserted by densification, interpolated, or given a derived
  heading/pitch/roll) gets at most `Estimated`. If the source quality is already worse (for example `Simulated`), it
  keeps the worse value. Quality is never improved by a calculation.
- A flight path is never better than its worst point. A densified path is therefore at most `Estimated`. For the
  `Simulated` demo data the path stays `Simulated`.
- **Reconstructed data is never shown as `Measured`.** In KML only data of an actual track of at least `Published`
  quality gets the "measured" (green) style. Estimated, reconstructed and simulated parts use the orange or blue
  planned styles and say so in their description.
- The KML data of each point also keeps the quality and the source name.
- If no source exists for a value, it is left empty (`null`) with quality `Unknown`. A number is never invented.
- M1 has only planned trajectories (blue). Actual trajectories come in M2.

See [calculations.md](calculations.md) for how the calculated values are made.
